# 我该从哪开始

这套文档按 [Diátaxis](https://diataxis.fr/) 分成四个象限。它们回答四种不同的问题，混在一起读会很累，所以先确认你现在要的是哪一种。

## 什么时候该看这个

| 你现在的情况 | 去哪 | 那个象限给你什么 |
| --- | --- | --- |
| 刚听说 mcsdev，想先看它跑起来 | [5 分钟快速上手](/get-started/quickstart) | 一条能跑通的最短路径，不解释原理 |
| 想系统学一遍，边做边理解 | [教程](/tutorial/) | 从零开始、每步可复制粘贴的长流程 |
| 有个具体任务要完成（只部署一个子项目 / 配自动重启 / 清理残留 jar） | [操作指南](/how-to/) | 只讲这一步怎么做，不铺陈背景 |
| 想搞懂它为什么这样设计 | [理解](/explanation/) | 设计取舍与边界，没有操作步骤 |
| 要查某个参数、某个字段的准确语义 | [参考](/reference/) | 完整的命令、参数、字段、默认值 |

## 四象限的边界

- **教程（Tutorials）** 是学习用的：你照着做，它保证结果。教程里不解释为什么，也不给分支选项。
- **操作指南（How-to guides）** 是任务用的：你已经有目标，只需要步骤。它假设你懂基础。
- **参考（Reference）** 是查的：准确、完整、干燥。它不教你做事，只描述事实。
- **理解（Explanation）** 是想通用的：为什么是 link 模式、为什么 clean 默认开、为什么用 hash 判等。

如果你不确定从哪进，就走这条：**快速上手 → 教程第一篇 → 遇到具体问题再查操作指南**。

## mcsdev 是什么

mcsdev 是一个本地 CLI（命令行工具，command-line interface），装在开发机上，不进服务器运行。它负责三件事：

1. **把构建产物放到位**：从 `build/libs/` 里挑出该部署的 jar，复制到测试服的 `plugins/`，顺手清掉同名的旧版本。
2. **让服务器加载它**：按你配置的策略重启服务器（或提醒你自己重启），然后探测端口确认它真的起来了。
3. **让这件事可重复**：以上行为全部写在项目里的 `mcsdev.yml`，而不是你脑子里或某个人的 shell 历史里。

它**不是**服务器插件，**不是**运维面板，**不是**热重载工具。这条边界写在[边界与非目标](/explanation/scope-and-non-goals)里。

## 两种使用姿势

mcsdev 有两条路径，它们在 `mcsdev.yml` 里由 `link` 和 `server` 二选一决定：

| | link 模式（外部服务器） | server 模式（mcsdev 自建） |
| --- | --- | --- |
| 服务器从哪来 | 你已有的那台开发服，mcsdev 只往里放 jar | `mcsdev new` 从 PaperMC 下载并建一台 |
| 启停谁负责 | 你（或你的脚本、你的面板） | mcsdev（`start` / `stop` / `restart`） |
| 默认重启策略 | `none`（只部署） | `mcsdev`（自己重启） |
| 适合谁 | 已经有一台跑着的开发服、monorepo 多插件共用一个服 | 从零开始，或想要一台干净的隔离环境 |

两种模式都用同一套 `init / config / ps / deploy / dev` 命令。差别只在 `link` 那一段怎么写，见 [mcsdev.yml 字段](/reference/mcsdev-yml#link-与-server-二选一)。
